## Why

nldesign vendors 344 Amsterdam Design System icons in `img/icons/` (plus 23 org logos in
`img/logos/`) and documents the filenames as a public API in `img/ICONS.md`, consumable by any
app via `IURLGenerator::imagePath('nldesign', 'icons/{Name}.svg')`. The vendored icon set is a
licensing defect, not just a style choice:

- `img/ICONS.md` and the canonical `openspec/specs/icon-assets/spec.md` (requirement "MPL-2.0
  License Notice Travels With the Assets") claim the icons are MPL-2.0. The upstream package
  itself says otherwise: `node_modules/@amsterdam/design-system-assets/LICENSE.md` reads
  **"The open-source licence does NOT apply to files in this directory. These are proprietary
  assets to the City of Amsterdam."** The Amsterdam design-system NOTICE restricts use of these
  brand assets to communication where the City of Amsterdam is the main communicator. nldesign
  redistributing them to arbitrary Dutch-government Nextcloud instances is exactly the use the
  notice forbids, and our own spec codifies a false licence claim.
- The shared Vue library already took the correct position:
  `nextcloud-vue/src/icons/ATTRIBUTION.md` states **"The proprietary City-of-Amsterdam icon set
  (`@amsterdam/design-system-assets`) is deliberately NOT included — its `LICENSE.md` marks it
  proprietary, so it must not be redistributed here."** nldesign shipping what nc-vue explicitly
  refuses to ship is a fleet inconsistency with legal exposure.
- `@conduction/nextcloud-vue` already bundles **1488 EUPL-compatible NL-government icons** as
  auto-generated data-URI packs (`src/icons/rvo.js` 1163 icons CC0-1.0, `src/icons/openGemeenten.js`
  256 icons CC0-1.0, `src/icons/denHaag.js` 69 icons EUPL-1.2; generated by
  `scripts/generate-nl-icons.mjs`, licences documented in `src/icons/ATTRIBUTION.md`). That is the
  canonical fleet home for NL-government icons (USER DIRECTIVE); nldesign should consume it, not
  maintain a parallel — and proprietary — set.
- `README.md` (line 321) even lists `@amsterdam/design-system-react-icons` as "government
  open-source, EUPL-compatible — approved 2026-03-15", which the upstream LICENSE.md contradicts.

**Known consumers of the Amsterdam filenames (fleet grep of `apps-extra/*/src`, `*/lib`, `*/js`,
2026-07-23), so the breakage is sized honestly:**

- **launchpad** — the archived tiles design
  (`launchpad/openspec/changes/archive/2026-03-21-tiles/specs/tiles/design.md:207`) documented an
  icon type `'nldesign'` whose value is a URL of the form `/apps/nldesign/img/icons/{Name}.svg`,
  **stored with `iconType: 'url'` in tile data** — so persisted tile configurations on live
  instances may reference Amsterdam filenames. The current launchpad editor catalogue is MDI-only
  (`launchpad/src/services/iconCatalogue.js`), so no live picker offers the URLs anymore, but
  `launchpad/src/components/__tests__/TileEditor.spec.js:38-61` still exercises
  `/apps/nldesign/img/icons/Star.svg` as a representative stored value.
- No other consumer of `imagePath('nldesign', 'icons/…')` was found in any fleet app's `src/`,
  `lib/` or `js/`. (openbuild consumes nldesign **token CSS** via `generateFilePath('nldesign',
  'css', 'tokens/…')` — unaffected by this change.)

Org logos in `img/logos/` are a different situation: they are huisstijl assets tied to token sets
(`token-sets.json` `theming.logo` entries) displayed as the respective organisation's own identity
on that organisation's own instance — nominative use, not icon-library redistribution. They stay.

## What Changes

- **BREAKING (asset removal, licence-driven):** Delete all 344 vendored Amsterdam Design System
  SVGs from `img/icons/`. The proprietary artwork cannot ship in any further release, so there is
  no grace release for the artwork itself.
- **New icon source of record:** add `@conduction/nextcloud-vue` as an npm devDependency and
  rewrite `scripts/build-icons.js` to materialize the three EUPL-compatible packs
  (`src/icons/rvo.js`, `src/icons/openGemeenten.js`, `src/icons/denHaag.js`) from their data-URI
  entries into real SVG files under `img/icons/<set>/<key>.svg` (`rvo/`, `open-gemeenten/`,
  `den-haag/`; 1488 icons total). The PHP-side consumption contract stays
  `imagePath('nldesign', 'icons/{set}/{key}.svg')` — no runtime dependency on nc-vue, no runtime
  JS: the packs are decoded at build time only.
- **One-release deprecation path for Amsterdam-only filenames:** a curated alias map
  (`scripts/icon-aliases.json`, legacy PascalCase name → replacement pack icon) makes the build
  additionally write the mapped **replacement artwork** under the legacy top-level filename
  (`img/icons/{Name}.svg`), so stored URLs (e.g. launchpad tile data) keep resolving for one
  release — serving EUPL-compatible artwork, never Amsterdam's. Legacy names with no reasonable
  equivalent 404 immediately and are listed in the changelog. The aliases are removed in the next
  minor release (tracked in `img/ICONS.md` and `CHANGELOG.md`).
- **Org logos stay:** `img/logos/` (23 files) becomes a static, checked-in asset directory;
  `scripts/build-icons.js` stops copying anything from the Amsterdam package (including its
  `logo/` directory) and never touches `img/logos/` again.
- Remove npm dependencies `@amsterdam/design-system-assets` and
  `@amsterdam/design-system-react-icons` from `package.json` (the latter after verifying it has
  zero references outside `package.json`/`README.md`).
- Regenerate `img/ICONS.md` from the new build script: new inventory (per-set counts, alias
  table with removal deadline), corrected licence attribution (CC0-1.0 / CC0-1.0 / EUPL-1.2 per
  set, pointing at nc-vue's `src/icons/ATTRIBUTION.md` as the source of record), updated usage
  snippet, and an explicit breaking-change note for the Amsterdam names.
- Update `tests/Unit/IconAssetsTest.php` (inventory/count/licence-notice assertions),
  `README.md`, and `docs/reference/icons.md` to the new counts, paths, and licence facts.
- Update the canonical `icon-assets` spec: the Amsterdam-set and MPL-2.0 requirements are
  replaced (see the delta), the consumption contract and naming-stability requirements are
  updated to the new set-prefixed layout plus alias lifecycle.
- Changelog entries: BREAKING removal (full list of removed names and their mapped aliases /
  "no equivalent"), the new inventory, and the alias-removal deadline (next minor release).

## Impact

- `img/icons/` — 344 files deleted, ~1488 + aliases generated (new subdirectories `rvo/`,
  `open-gemeenten/`, `den-haag/`).
- `img/ICONS.md` — regenerated (new inventory, licences, alias table).
- `img/logos/` — untouched content; ownership shifts to static checked-in assets.
- `scripts/build-icons.js` — rewritten (decode nc-vue data-URI packs; stop copying Amsterdam
  assets and logos).
- `scripts/icon-aliases.json` — new curated legacy-name alias map.
- `package.json` / `package-lock.json` — drop both `@amsterdam/*` deps, add
  `@conduction/nextcloud-vue` (devDependency).
- `tests/Unit/IconAssetsTest.php` — updated inventory, pairing, licence-notice assertions.
- `README.md`, `docs/reference/icons.md` — counts, sources, licences, usage snippet.
- `CHANGELOG.md` — breaking-change entry + alias table + removal deadline.
- `openspec/specs/icon-assets/spec.md` — via delta in this change.
- Downstream (outside this repo): launchpad tile data referencing
  `/apps/nldesign/img/icons/{Name}.svg` keeps working for aliased names for one release;
  `launchpad/src/components/__tests__/TileEditor.spec.js` fixture URLs should migrate to the new
  paths (launchpad-side follow-up, not part of this change).
